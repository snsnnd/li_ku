## 2. 生成、检查

在项目根目录，WSL/Linux：

```bash
uv venv /tmp/opencode/asrs-v02-venv
uv pip install --python /tmp/opencode/asrs-v02-venv/bin/python -r cad/v02/requirements.txt
/tmp/opencode/asrs-v02-venv/bin/python cad/v02/asrs_v02.py --validate
PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 /tmp/opencode/asrs-v02-venv/bin/python -m pytest cad/v02/test_asrs_v02.py -q --junitxml=model/V02/tests.xml
/tmp/opencode/asrs-v02-venv/bin/python cad/v02/verify_motion.py --step 5
/tmp/opencode/asrs-v02-venv/bin/python cad/v02/engineering_checks.py
/tmp/opencode/asrs-v02-venv/bin/python cad/v02/render_previews.py
```

环境中有ROS的全局pytest插件，因此禁用插件自动发现；否则会把与本项目无关的ROS依赖缺失当成测试失败。

生成器仅支持已冻结的4×5版本，不提供“随便改一个列数就自动扩展所有节点”的虚假能力。变更尺寸必须同步复核连接、保护空间和全部测试。

`asrs_v02.py`会写`model/V02`中的生成产物；不是只读脚本。不会运行V01生成器，也不会覆写V01的模型、STL、说明书和验证报告。

运动采样包括名义5 mm以内的Y采样、10 mm的Z采样、15 mm的X采样、10°的销动作采样，以及另行记录间距的间隙补偿工况。它不是连续碰撞检测、接触动力学或真实电机控制。

## 3. SolidWorks 原生转换

Windows中先打开有许可证的SW2025，然后：

```powershell
D:\立库\cad\v02\ExportSolidWorksV02.ps1
# 已有native目录时必须选择新目录，不静默覆盖：
D:\立库\cad\v02\ExportSolidWorksV02.ps1 -Output D:\立库\model\V02\native_review_02
```

- 编译器为系统.NET Framework C#编译器，使用项目已有官方Interop DLL。
- 可执行文件放在`cad/ExportSolidWorksV02.exe`，与Interop位于同目录，避免运行时找不到程序集。
- 原生转换器仅导入manifest中的V02零件，检查每件单实体、包围尺寸及逐组件变换回读。
- 本机默认模板存在配置问题，会导致STEP导入失败。因此导入期间临时设置了明确的GB零件/装配模板，并暂时使用直接导入。`finally`尝试恢复原设置，但本次COM断开导致恢复失败；请按[设置确认说明](V02_SolidWorks设置确认.md)人工确认。
- 不调用`ExitApp()`，不关闭用户原有文档，也不覆盖旧原生输出目录。
- 原生部件被固定以保存审核姿态。**没有建立真实运动配合、没有保存已验收的Motion Study，不把脚本位姿采样冒充它们。**
- 失败尝试保留于独立诊断目录；只有`solidworks_validation.json`明确成功，才可称该次原生输出完成。
